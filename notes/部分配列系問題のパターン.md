## パターン1: 累積和 + HashMap

### 核心アイデア
`sum(nums[i..j]) = prefix[j+1] - prefix[i]` という変換で、**区間の和に関する問い**を **2点の差に関する問い** に帰着させる。
「prefix[i] を記録しながら右に進む」ことで O(n) にする。

### 認識の手がかり
- 「和が k になる連続部分配列」
- 「和が k の倍数になる連続部分配列」
- 要素に負数があってもよい（Sliding Window が使えない場面で活きる）

### 考え方の手順
1. `sum(nums[i..j])` を `prefix[j+1] - prefix[i]` に書き換える
2. 条件式を `prefix[i] = f(prefix[j+1])` の形に整理する
3. HashMap に `{prefix値: インデックス}` を記録しながら j を進める
4. 各 j で「対応する prefix[i] が記録済みか」をチェックする

### テンプレート
```python
seen = {0: -1}   # prefix[0] = 0, インデックス -1 で初期化
prefix = 0
for j, x in enumerate(nums):
    prefix += x
    key = (条件から定まる prefix[i] の値)
    if key in seen:
        # nums[seen[key]+1 .. j] が条件を満たす
        ...
    else:
        seen[prefix] = j
```

### 例: [Continuous Subarray Sum](https://leetcode.com/problems/continuous-subarray-sum/)(#523, 和が k の倍数、長さ ≥ 2)

条件を整理する:
```
(prefix[j+1] - prefix[i]) % k = 0
=> prefix[j+1] % k = prefix[i] % k
```
-> HashMap のキーを「余り」にすればよい。

```python
class Solution:
    def checkSubarraySum(self, nums: List[int], k: int) -> bool:
        first = {0: 0}
        prefix = 0

        for i, num in enumerate(nums, start=1):
            prefix += num
            r = prefix % k

            if r in first:
                if i - first[r] >= 2:
                    return True
            else:
                first[r] = i

        return False
```

## パターン2: Sliding Window

### 核心アイデア
`[left, right]` という窓を右に広げながら、**「窓を縮められる条件」が単調**であることを利用して left も右に動かす。
right も left も最大 n 回しか動かないので O(n)。

### 認識の手がかり
- 「条件を満たす最短／最長の連続部分配列」
- 「窓が条件を満たすかどうか」が単調に判定できる（要素が非負で和の増減が一方向、など）
- 窓の中の種類数・頻度に上限がある

### 使えない場面
要素に負数があると、窓を広げても和が必ずしも増えない。→ 累積和 + HashMap か Kadane へ。

### 考え方の手順
1. 「窓をどう伸縮させれば条件が単調に変化するか」を確認する
2. right を先に動かし、窓に right の要素を加える
3. 条件を満たしている限り left を動かして窓を縮める
4. 各ステップで答えを更新する

### テンプレート
```python
left = 0
state = (窓の状態: 和・頻度マップ等)
ans = 初期値

for right in range(len(nums)):
    state に nums[right] を加える

    while 窓が「縮められる」条件を満たす:
        ans = update(ans, right - left + 1)
        state から nums[left] を取り除く
        left += 1

return ans
```

### 例: Minimum Size Subarray Sum (#209, 和 ≥ target の最短部分配列)

「縮められる条件」= 今の窓の和がすでに target 以上 → 縮めても条件を満たせる可能性がある。

```python
left = 0
total = 0
ans = float('inf')

for right in range(len(nums)):
    total += nums[right]
    while total >= target:
        ans = min(ans, right - left + 1)
        total -= nums[left]
        left += 1

return ans if ans != float('inf') else 0
```

## パターン3: Two Pointer

### 核心アイデア
両端 `left, right` から内側に向けてポインタを動かす。
「left を増やすと値が増える、right を減らすと値が減る」という**単調性**を使い、O(n) で探索する。

### 認識の手がかり
- ソート済み配列（またはソートしてよい）で、**2要素以上の組み合わせ**を探す
- 「和が target に等しい」「面積を最大化する」など、2つの値のトレードオフが単調

### Sliding Window との概念的な違い
- Sliding Window: `[left, right]` の範囲の中身を集計している（「今この窓を見ている」）
- Two Pointer: `[left, right]` は未探索の候補範囲（「ここに答えがあるはず」という絞り込み）

### 考え方の手順
1. 配列をソートする（必要なら）
2. left = 0, right = n-1 で初期化
3. 現在の値を評価し、target より小さければ left を増やし、大きければ right を減らす
4. left ≥ right になったら終了

### テンプレート
```python
nums.sort()   # 必要なら
left, right = 0, len(nums) - 1

while left < right:
    val = f(nums[left], nums[right])
    if val == target:
        記録; left += 1; right -= 1
    elif val < target:
        left += 1
    else:
        right -= 1
```

### 例: 3Sum (#15, 和が 0 の3要素の組)

1要素を外側のループで固定し、残り2要素を two pointer で探す。O(n²)。
重複の除去は「直前と同じ値ならスキップ」で対処する。

```python
nums.sort()
res = []
for i in range(len(nums) - 2):
    if i > 0 and nums[i] == nums[i-1]:
        continue
    left, right = i + 1, len(nums) - 1
    while left < right:
        s = nums[i] + nums[left] + nums[right]
        if s == 0:
            res.append([nums[i], nums[left], nums[right]])
            while left < right and nums[left] == nums[left+1]: left += 1
            while left < right and nums[right] == nums[right-1]: right -= 1
            left += 1; right -= 1
        elif s < 0:
            left += 1
        else:
            right -= 1
```

## パターン4: 二分探索

「最適値を求めよ」という問いに対し、**答えの候補に単調性があること**を見抜いて判定問題に帰着させる。
主に 4 つのサブパターンがある。

---

### 4a: Binary Search on Answer (答えの値に対する二分探索)

### 核心アイデア
「最適値 X を求めよ」という最適化問題を「X 以下（以上）で実現可能か」という**判定問題**に変換する。
判定結果が X に対して単調（`F F F T T T`）なら、その境界を二分探索できる。

### 認識の手がかり
- 「最小化せよ」「最大化せよ」という問いに対し、「X 以下で可能か」という判定関数が O(n) で書ける
- 判定の真偽が答えの候補値に対して単調になる

### 考え方の手順
1. 答えの候補範囲（下限・上限）を決める
2. 「mid 以下（以上）で条件を満たせるか」という判定関数を書く（貪欲で O(n) になることが多い）
3. 判定が True なら右（または左）に絞り、False なら逆に絞る

### テンプレート
```python
left, right = 下限, 上限

while left < right:
    mid = (left + right) // 2
    if can_achieve(mid):
        right = mid       # mid で達成できる → もっと小さくできるか試す
    else:
        left = mid + 1    # mid では無理 → 大きくする

return left
```

### 例: Split Array Largest Sum (#410, 区間分割の最大値を最小化)

「最大区間和 ≤ X で m 個以内に分割できるか」が単調 → 二分探索できる。
判定は「X を超えたら区切る」という貪欲で O(n)。

```python
def can_split(nums, m, limit):
    count, current = 1, 0
    for x in nums:
        if x > limit: 
	        return False
	        
        if current + x > limit:
            count += 1; 
        
        current += x
    return count <= m

left, right = max(nums), sum(nums)
while left < right:
    mid = (left + right) // 2
    if can_split(nums, m, mid): right = mid
    else: left = mid + 1
return left
```

**Capacity To Ship Packages との対応:** 「m 日で荷物を順番に運ぶ最小キャパシティ」も同じ構造。区間 = 1日分の荷物、最大区間和 = 積載量。

### 4b: 長さに対する二分探索

### 核心アイデア
「長さ L の部分配列（部分列）が存在するか？」という判定に単調性がある場合に使う。
L が大きいほど条件を満たしにくい（`T T T F F F`）ので、その境界を二分探索する。

### 認識の手がかり
- 「最長の〇〇を求めよ」という問いで、「長さ L が可能か？」の判定関数が O(n) で書ける
- Sliding Window で書いた判定関数がそのまま使えることが多い

### 考え方の手順
1. 「長さ L が可能か？」を判定する関数を書く
2. `T T T F F F` の境界を `while left < right` で二分探索する
3. 判定関数の中身は Sliding Window や貪欲になることが多い

### 例: Longest Repeating Character Replacement (#424, 最大 k 回の置換で同じ文字に揃えられる最長部分配列)

「長さ L の窓で `L - max_count <= k` が満たせるか？」が判定関数になる。
最大長を求めるので `T T T T F F F` の形 → 右端（最大の T）を探す二分探索。

```python
def characterReplacement(s, k):
    def can_make_uniform(L):
        count = {}
        max_count = 0
        for right in range(len(s)):
            count[s[right]] = count.get(s[right], 0) + 1
            max_count = max(max_count, count[s[right]])
            if right >= L:
                count[s[right - L]] -= 1
            if L - max_count <= k:
                return True
        return False

    left, right = 1, len(s)
    while left < right:
        mid = (left + right + 1) // 2   # 最大値を求めるので切り上げ
        if can_make_uniform(mid):
            left = mid
        else:
            right = mid - 1
    return left
```

**注:** この問題は通常 Sliding Window で O(n) に解く。二分探索版は O(n log n) だが、「長さへの二分探索」のパターンを学ぶ典型として有用。

### 4c: Prefix Sum + 二分探索

### 核心アイデア
prefix 配列が**単調増加**（要素が非負）のとき、`bisect` で特定の和を持つ区間端を O(log n) で探せる。
各 i について「prefix[j] - prefix[i] >= target を満たす最小 j」を二分探索する。

### 使う場面
- 要素が非負で prefix が単調（→ Sliding Window で O(n) も可だが、2D や複雑な条件では二分探索が有効）
- Minimum Size Subarray Sum (#209) の別解: O(n log n)

```python
import bisect

prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)

ans = float('inf')
for i in range(len(prefix)):
    j = bisect.bisect_left(prefix, prefix[i] + target)
    if j < len(prefix):
        ans = min(ans, j - i)
```

### 4d: LIS O(n log n) — 状態管理の二分探索

### 核心アイデア
答えを二分探索しているのではなく、`tails` 配列の更新を `bisect_left` で O(log n) にする。
`tails[i]` = 長さ i+1 の増加部分列の末尾の**最小値**（tails 自体は実際の LIS ではない）。

### 考え方の手順
1. `tails = []` で初期化
2. 各 x について `bisect_left(tails, x)` で挿入位置 pos を求める
3. `pos == len(tails)` なら末尾に追加（LIS が伸びた）、そうでなければ `tails[pos] = x`（より小さい末尾値に更新）
4. `len(tails)` が答え

```python
from bisect import bisect_left

def lengthOfLIS(nums):
    tails = []
    for x in nums:
        pos = bisect_left(tails, x)
        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x
    return len(tails)
```

## パターン5: Kadane's Algorithm

### 核心アイデア
各位置で「前の部分配列を延長する」か「ここから再スタートする」かを選ぶ。
`cur < 0` になった時点で延長するメリットがなくなるため切り捨てる。

### 認識の手がかり
- 「最大連続部分和」
- 要素に負数があり Sliding Window が使えない
- O(n) で解く必要がある

### 考え方の手順
1. `cur = nums[0]`（現在の連続部分和）で初期化
2. 各要素で `cur = max(nums[i], cur + nums[i])` を取る
3. `max_sum` を随時更新する

### 例: Maximum Subarray (#53)

```python
max_sum = cur = nums[0]
for x in nums[1:]:
    cur = max(x, cur + x)
    max_sum = max(max_sum, cur)
return max_sum
```

## パターン6: DP (非連続部分列)

### 核心アイデア
**要素を飛ばして選べる**部分列の最適化問題。`dp[i]` = インデックス i を末尾とする部分列に関する最適値、として定義することが多い。
前の全状態（または特定の状態）を参照して遷移する。

### 連続 vs 非連続の使い分け
- 連続部分配列（subarray）→ 累積和 / Sliding Window / Kadane
- **非連続部分列（subsequence）→ DP**

### 認識の手がかり
- 「部分列」「subsequence」という言葉がある
- 要素を飛ばして選べる
- 「最長増加部分列 (LIS)」「最長共通部分列 (LCS)」「編集距離」など

### 考え方の手順
1. `dp[i]` の定義を「i を使った（または i まで考慮した）最適値」で決める
2. 遷移式を考える（前の状態のどれを参照するか）
3. ボトムアップで埋める、`max(dp)` などを返す

### 例: LIS (#300, 最長増加部分列) O(n²)

```python
def lengthOfLIS(nums):
    n = len(nums)
    dp = [1] * n   # dp[i] = nums[i] を末尾とする LIS の長さ
    for i in range(1, n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)
```

O(n log n) にするには **4d の二分探索 (tails 配列)** を使う。

## パターン7: 単調スタック

### 核心アイデア
「各要素の左右で最初に現れる大きい（または小さい）要素」を O(n) で求める。
スタックを単調（増加または減少）に保ちながら処理し、単調性を壊す要素が来たときにポップして答えを確定させる。

### 認識の手がかり
- 「次の大きい要素」「前の小さい要素」
- 「ヒストグラムの最大長方形」
- 各要素に対して「自分より大きい（小さい）最近傍」が必要:

### 考え方の手順
1. 単調増加か単調減少かを決める（「次の大きい要素」なら単調減少スタックを使い、破壊されたときに答えが確定）
2. 各要素を処理するとき、スタック top を破壊するなら pop して確定、しないなら push
3. スタックに残った要素は「対応する要素が存在しない」

### テンプレート（次の大きい要素）

```python
stack = []   # 単調減少スタック（インデックスを格納）
ans = [-1] * len(nums)

for i in range(len(nums)):
    while stack and nums[stack[-1]] < nums[i]:
        j = stack.pop()
        ans[j] = nums[i]   # nums[j] の「次の大きい要素」が nums[i]
    stack.append(i)

return ans
```

### 例: Daily Temperatures (#739)

```python
def dailyTemperatures(temperatures):
    n = len(temperatures)
    ans = [0] * n
    stack = []

    for i in range(n):
        while stack and temperatures[stack[-1]] < temperatures[i]:
            j = stack.pop()
            ans[j] = i - j
        stack.append(i)

    return ans
```

## パターン8: 単調キュー (Sliding Window Maximum)

### 核心アイデア
固定長の窓の中の最大値（最小値）を O(n) で求める。
deque の**先頭が常に現在の窓の最大値**（のインデックス）になるよう、末尾に追加するときに不要な要素を捨てる。

### Sliding Window との違い
- Sliding Window: 窓の「和」や「個数」を集計する
- 単調キュー: 窓の「最大値・最小値」を O(1) で取り出す

### 認識の手がかり
- 「スライディングウィンドウの最大値（最小値）」
- 窓サイズ固定で、全窓の max/min が必要

### 考え方の手順
1. deque にインデックスを格納し、単調減少（最大値を求める場合）を維持する
2. 新要素を追加するとき、末尾から新要素より小さいものを捨てる
3. 先頭が窓の外に出たら捨てる
4. deque の先頭が窓の最大値

### テンプレート

```python
from collections import deque

def maxSlidingWindow(nums, k):
    dq = deque()   # 単調減少デック（インデックスを格納）
    ans = []

    for right in range(len(nums)):
        # 末尾: 新要素より小さいものは不要
        while dq and nums[dq[-1]] <= nums[right]:
            dq.pop()
        dq.append(right)

        # 先頭が窓の外に出たら捨てる
        if dq[0] < right - k + 1:
            dq.popleft()

        # 窓がサイズ k になったら最大値を記録
        if right >= k - 1:
            ans.append(nums[dq[0]])

    return ans
```

### 例 1: Sliding Window Maximum (#239)
上のテンプレートがそのまま使える。

### 例 2: Jump Game VI (#1696, DP + sliding window max)

`dp[i] = max(dp[i-k..i-1]) + nums[i]` という遷移。「直近 k ステップの最大 dp 値」を O(1) で取るために単調キューを使う。

```python
from collections import deque

def maxResult(nums, k):
    n = len(nums)
    dp = [0] * n
    dp[0] = nums[0]
    dq = deque([0])   # 単調減少デック（dp 値の大きい順にインデックスを管理）

    for i in range(1, n):
        if dq[0] < i - k:       # 先頭が窓の外に出たら捨てる
            dq.popleft()

        dp[i] = dp[dq[0]] + nums[i]

        while dq and dp[dq[-1]] <= dp[i]:   # 末尾: 新しい dp[i] より小さいものは不要
            dq.pop()
        dq.append(i)

    return dp[-1]
```

素直に書くと O(nk)、単調キューで O(n)。

## 判断軸まとめ

| 問いの形               | 単調性・制約       | パターン                              |
| ------------------ | ------------ | --------------------------------- |
| 和が条件を満たす連続部分配列     | 負数あり可        | 累積和 + HashMap                     |
| 条件を満たす最短／最長の連続部分配列 | 窓の伸縮が単調      | Sliding Window                    |
| 窓の最大値・最小値          | 固定長の窓        | 単調キュー                             |
| ソート済み配列で和の組み合わせ    | ソート可         | Two Pointer                       |
| 最適値を最小化／最大化        | 判定が単調        | 二分探索 4a (Binary Search on Answer) |
| 最長の〇〇が可能か          | 長さに対して単調     | 二分探索 4b (長さへの二分探索)                |
| 単調な prefix への区間クエリ | prefix が単調増加 | 二分探索 4c (Prefix Sum + 二分探索)       |
| 最長増加部分列 O(n log n) | 非連続          | 二分探索 4d (LIS の tails 配列)          |
| 最大連続部分和            | 負数あり         | Kadane's Algorithm                |
| 非連続部分列の最適化         | 飛ばして選べる      | DP (dp[i] の遷移)                    |
| 次の大きい／小さい要素        | スタック単調性      | 単調スタック                            |
