## BFS vs DFS の使い分け

| | BFS | DFS |
|---|---|---|
| データ構造 | Queue | Stack / 再帰 |
| 向いている問題 | 最短距離・最短経路・レベル数 | 経路の存在確認・バックトラッキング |
| 計算量 | O(V + E) | O(V + E) |

> BFS・DFS はそのままでは問題を解けない。必ず問題に合わせて修正が必要。

## 応用問題① Course Schedule

### 問題
- n個の講義（0〜n-1）と前提条件のリストが与えられる
- 全講義を受けられる順番を返せ（不可能なら空配列）
- 例：`[0,1]` → 1 が 0 の前提条件

### グラフとしての見方
- ノード = 講義
- エッジ = 前提条件の関係（有向グラフ）
- **サイクルがあれば受講不可能**

### アプローチ① DFS（taken/seen、通常方向）

**発想：** 前提条件を先に処理 → バックトラック時に受講 → 最後に逆順で返す

```python
def findOrder(numCourses, prerequisites):
    graph = {i: [] for i in range(numCourses)}
    for course, pre in prerequisites:
        graph[pre].append(course)   # pre → course（通常方向）

    taken = set()   # 受講済み
    seen  = set()   # 今のDFS中に訪問済み（サイクル検出用）
    output = []

    def dfs(course):
        if course in seen:    # サイクル検出
            return True
        if course in taken:   # 受講済みはスキップ
            return False
        seen.add(course)
        for next_course in graph[course]:
            has_cycle = dfs(next_course)
            if has_cycle:
                return True
        seen.remove(course)
        taken.add(course)
        output.append(course)
        return False          # サイクルなしで正常終了

    for c in range(numCourses):
        has_cycle = dfs(c)
        if has_cycle:
            return []
    return output[::-1]
```

**ポイント：**
- `taken`：受講済み（再訪不要）
- `seen`：今のDFSパス上で訪問中（サイクル = 同じノードに再到達）
- エッジが `pre → course` なので、深い方（前提条件）から先に `output` に入る → 最後に `[::-1]`

### アプローチ② DFS（3状態）

**発想：** `taken`/`seen` の2つを `UNVISITED / VISITING / VISITED` の1つにまとめる

```python
def findOrder(numCourses, prerequisites):
    graph = {i: [] for i in range(numCourses)}
    for course, pre in prerequisites:
        graph[pre].append(course)

    UNVISITED, VISITING, VISITED = 0, 1, 2
    state = [UNVISITED] * numCourses
    output = []

    def dfs(course):
        if state[course] == VISITING:   # サイクル検出
            return True
        if state[course] == VISITED:    # 処理済みはスキップ
            return False
        state[course] = VISITING
        for next_course in graph[course]:
            has_cycle = dfs(next_course)
            if has_cycle:
                return True
        state[course] = VISITED
        output.append(course)
        return False

    for c in range(numCourses):
        has_cycle = dfs(c)
        if has_cycle:
            return []
    return output[::-1]
```

**ポイント：**
- `taken`/`seen` の役割が `VISITED`/`VISITING` に対応
- セットの追加・削除がなく配列アクセスだけなので定数倍速い

### アプローチ③ BFS（Kahn's Algorithm / トポロジカルソート）

**発想：** 前提条件が0の講義から先に受ける → 受けたら隣の講義の前提条件を1減らす → 0になったら受講可能

```python
from collections import deque

def findOrder(numCourses, prerequisites):
    graph = {i: [] for i in range(numCourses)}
    in_degree = [0] * numCourses   # 残り前提条件の数

    for course, pre in prerequisites:
        graph[pre].append(course)
        in_degree[course] += 1

    queue = deque([c for c in range(numCourses) if in_degree[c] == 0])
    output = []

    while queue:
        course = queue.popleft()
        output.append(course)
        for next_course in graph[course]:
            in_degree[next_course] -= 1
            if in_degree[next_course] == 0:
                queue.append(next_course)

    return output if len(output) == numCourses else []
```

**ポイント：**
- BFSのキューへの追加条件を変更：「in_degree が0になったとき」だけ追加
- サイクルがあると一部の講義の in_degree が永遠に0にならない → `len(output) == numCourses` で判定
- 逆順不要（最初から正しい順序で出力される）
- `visited` 管理が不要：in_degree が0になるのは全前提条件を処理し終えた1回だけなので、同じノードがキューに2回入ることは構造上ありえない（DFS では複数パスから同じノードに到達できるため `taken`/`VISITED` が必要だった）

---

### 計算量（V = 講義数、E = 前提条件数）

| | 時間 | 空間 |
|---|---|---|
| DFS ①②共通 | O(V + E) | O(V + E) |
| BFS ③ | O(V + E) | O(V + E) |

**時間：**
- グラフ構築：O(V + E)
- DFS：各ノード最大1回、各エッジ最大1回 → O(V + E)
- BFS：各ノードはキューに最大1回、in_degree のデクリメントはE回 → O(V + E)

**空間：**
- 隣接リスト：キーV個 + エントリE個 → O(V + E)（支配項）
- DFS のみ：再帰スタックが最悪 O(V)（一本鎖のとき）→ スタックオーバーフローに注意

## 応用問題② Word Ladder

### 問題
- `beginWord`、`endWord`、単語リストが与えられる
- 1文字ずつ変えながら `beginWord` → `endWord` に変換する
- 変換の各ステップの単語は単語リストに含まれていなければならない
- **最短変換ステップ数**を返せ

### グラフとしての見方
- ノード = 単語
- エッジ = 1文字だけ異なる単語同士
- **最短距離 → BFS**

### 隣接単語の求め方（スロットマシン法）
隣接リストを事前に作らず、各位置のアルファベット26文字を総当たりして単語リストに存在するか確認する。英字26文字固定なので定数時間。

時間計算量：O (N *L^2) 空間計算量：O (N *L)
```python
from collections import deque

def ladderLength(beginWord, endWord, wordList):
    word_set = set(wordList)
    if endWord not in word_set:
        return 0

    queue = deque([beginWord])
    visited = {beginWord}
    distance = 1

    while queue:
        size = len(queue)           # 現在の距離にある単語数
        for _ in range(size):
            word = queue.popleft()
            if word == endWord:
                return distance
            chars = list(word)
            for i in range(len(chars)):
                original = chars[i]
                for c in 'abcdefghijklmnopqrstuvwxyz':
                    chars[i] = c
                    candidate = ''.join(chars)
                    if candidate in word_set and candidate not in visited:
                        visited.add(candidate)
                        queue.append(candidate)
                chars[i] = original   # 元の文字に戻す
        distance += 1

    return 0
```

**ポイント：**
- `size = len(queue)` でレベルごとに処理 → `distance` をレベル単位でインクリメント
- 文字列操作より配列操作の方が安い → `list(word)` に変換してから操作
- 隣接リストを作らない代わりに、毎回26文字を試す（定数コストなので問題なし）
