# 再帰

## 基本的なイメージ：木の全ノードに人を立たせる

各ノードに人を配置し、上司・部下の関係で仕事を分担する。

```
        A
       / \
      B   C
     / \
    D   E
```

- D・E にいる人は自分の結果を B に報告する
- B にいる人は D・E の報告を受け取り、自分の処理をして A に報告する
- 各人は「自分が認識できる範囲だけ」を知っている（これが重要）

人間を置く理由：ノードのような抽象的なものの気持ちは分からないが、人間には共感できるから。

---

## 再帰を書く前に決めること

1. 何を渡すのか（引数）
2. 何を返してもらうのか（返り値）
3. 部下の結果と自分の情報をどう組み合わせるか
4. 基底ケース（base case）は何か
5. なぜ必ず終わるのか（単調減少な何かが存在するか）
6. 再帰の深さの限界を考えているか

---

## 例1：Reverse Linked List

```
1 -> 2 -> 3 -> 4 -> 5
```

各ノードに人が立っている。5番目の人は後ろに誰もいないので「私自身が先頭で末尾」と返す。4番目の人は「5番目のひっくり返した結果の末尾に自分をつなぐ」と処理する。

```python
def reverseList(self, head):
    if not head or not head.next:
        return head
    new_head = self.reverseList(head.next)
    head.next.next = head  # 末尾に自分をつなぐ
    head.next = None
    return new_head
```

## 例2：ペアを返す再帰（線形時間化）— Diameter of Binary Tree

素朴に「各ノードで左右の高さを再計算」すると O(N²)。
解決策：**「高さ」と「直径」の両方を同時に返す**。

```python
def diameterOfBinaryTree(self, root):
    def dfs(node):
        if not node:
            return 0, 0  # (height, diameter)
        left_h, left_d = dfs(node.left)
        right_h, right_d = dfs(node.right)
        height = max(left_h, right_h) + 1
        diameter = max(left_d, right_d, left_h + right_h)
        return height, diameter

    _, result = dfs(root)
    return result
```

部下に「高さと直径の両方を持って戻ってきてください」と依頼する形。

## 末尾再帰

### 核心：「再帰呼び出しの後に何もしない」

通常の再帰は、部下から結果が返ってきた後に**自分の仕事が残っている**。

```python
def reverse(head):
    new_head = reverse(head.next)  # 部下に頼む
    head.next.next = head          # 返ってきた後に自分の仕事がある
    head.next = None
    return new_head
```

末尾再帰は、呼び出す前に自分の仕事を全部終わらせ、部下の結果を**そのまま返すだけ**。

```python
def reverse(head, acc=None):
    if not head:
        return acc
    nxt = head.next
    head.next = acc            # 呼び出す前に自分の仕事を終わらせる
    return reverse(nxt, head)  # 部下の結果をそのまま返す
```

### accumulator を引数に持つ理由

通常の再帰は「帰り道で仕事をする」→ スタックを積み続ける。

```
reverse(1) 待機中
  reverse(2) 待機中
    reverse(3) 待機中
      reverse(4) 待機中
        reverse(5) → 返す
      ← ここで仕事（スタック必要）
    ← ここで仕事（スタック必要）
```

末尾再帰は「行き道で仕事をする」→ acc に完成途中の結果を持ち歩き、帰り道に何もしない。

```
reverse(1, None)
  reverse(2, 1→None)
    reverse(3, 2→1→None)
      reverse(4, 3→2→1→None)
        reverse(None, 5→4→3→2→1→None) → そのまま返す
```

### なぜ最適化に使われるのか

末尾再帰は「もう帰り道に何もしないので、今のスタックフレームを捨てて次のフレームに上書きしていい」とコンパイラが判断できる（末尾呼び出し最適化 / TCO）。

```
通常の再帰: スタックが N 段積まれる → O(N) スタック空間
末尾再帰(TCO あり): スタックは常に1段 → O(1) スタック空間
```

| 言語 | TCO |
|------|-----|
| C/C++ | コンパイラが最適化することが多い（保証はない）|
| Haskell / Scheme | 言語仕様として保証 |
| Python | **なし**（`sys.setrecursionlimit` を超えるとエラー）|
| Java | **なし**（JVM の制約）|

Python・Java では末尾再帰でも深い再帰はスタックオーバーフローになるため、自分でループに変換する必要がある。

## 再帰とループの変換

### 変換の流れ
```
再帰 → 末尾再帰 → ループ
```

`return f(new_args)` を `args = new_args; continue` に置き換えるだけ。

```python
# 末尾再帰
def reverse(head, acc=None):
    if not head:
        return acc
    nxt = head.next
    head.next = acc
    return reverse(nxt, head)

# ループ（機械的変換）
def reverse(head):
    acc = None
    while head:
        nxt = head.next
        head.next = acc
        head, acc = nxt, head
    return acc
```

### 帰りがけの処理がある場合（スタックを使う）

```python
# ツリーの後順 traversal をスタックで
stack = [(root, False)]
while stack:
    node, visited = stack.pop()
    if not node:
        continue
    if visited:
        process(node)  # 帰りがけの処理
    else:
        stack.append((node, True))    # 帰り用に再度積む
        stack.append((node.right, False))
        stack.append((node.left, False))
```

## 再帰の深さの限界

| 言語 | デフォルト |
|------|-----------|
| Python | 1000（`sys.setrecursionlimit` で変更可） |
| Java | 約1M |
| C/C++ | 約10M |
| Rust | 2M |

N = 10⁵ の線形連結リストなど深さが大きくなりうる場合はループへの変換を検討する。

## グローバル変数・メンバ変数を使う再帰の問題点

```python
class Solution:
    def __init__(self):
        self.result = 0  # ← 問題

    def solve(self, root):
        self._dfs(root)
        return self.result
```

- **2回呼べない**（`self.result` がリセットされない）
- **スレッドセーフでない**

解決策：返り値として結果を返すか、引数として渡す。

## まとめ

| | 通常の再帰 | 末尾再帰 |
|--|----------|---------|
| 仕事のタイミング | 帰り道 | 行き道 |
| スタック | N 段積まれる | TCO があれば 1 段 |
| accumulator | 不要 | 必要（状態を引数で持ち歩く）|
| ループへの変換 | 複雑 | 機械的に変換できる |

| 場面 | 手法 |
|------|------|
| 基本 | 木の各ノードに人を立てて「渡す・返す」を決める |
| 複数値が必要 | ペアを返す再帰で線形時間化 |
| スタック深さが心配 | 末尾再帰 → ループ変換 |
| 帰りがけの処理 | スタックに `(node, visited)` を積む |
| 状態の共有 | メンバ変数ではなく返り値か引数で渡す |
